# 哪些导航权重值得编辑

核查日期：2026-11-03。已读 Weight-Space Programming 博客，核查三篇导航论文、公开代码及直接相关工作。以下为研究建议与静态代码结论；未下载或加载导航检查点、未编辑权重、未运行导航实验。不是完整 SOTA 排名或新颖性审查。

**建议先用 Falcon 的动作输出层验证，再把成功机制迁移到 DPet；NavThinker 对未来特征的读取权重是第二条更有针对性的研究路线。**

## 2. 博客能迁移的思路

[博客实验8及附加实验](https://rikiyat.github.io/blog/weight-space-programming/)更支持“解除局部能力阻塞”：Qwen的收益主要来自消除重复循环，无明显循环问题的Gemma未获得可靠提升。大模型编辑使用练习数据与批量反馈，因此无反向传播不等于零数据、零算力。它没有证明一般导航能力可以通过少量编辑凭空获得。

动作头之所以值得先试，是因为它紧贴行为输出、参数量小、修改容易对照，并不意味着它已被证明是最有效的层。核心前提是隐藏状态已经携带所需信息；若根本没看见行人、记不住路线或未学会语言落地，单改最后一层通常不足。

设动作logits为 `z=Wh+b`，可考虑秩一更新 `W'=W+αuvᵀ`，得到 `z'=z+αu(vᵀh)`。v选择已诊断的隐藏特征方向，u规定如何重新分配四动作偏好。这是候选数学形式，不是已发现的有效方向，也没有自动的“危险时才启动”门。少量权重变化可能影响大量状态；需证明正常状态上的修改足够小。如果从数据估计v或搜索α，必须记录这些数据与反馈预算。

## 3. 三种容易选错的靶点

1. **Falcon训练辅助头与critic。** 公开act路径不调用人数/位置/轨迹辅助损失模块；critic的输出不进入动作选择。保持actor和共享表征不变时，纯推理阶段只改这些独立分支不会改变动作。训练时它们影响共享表征是另一回事。
2. **NavThinker在LayerNorm之前的整体缩放。** `lookahead_per_action_fc`后跟LayerNorm，整体正数缩放可能被大幅抵消。要测试未来信息的贡献，应优先干预actor读取未来表征的列块，并保持当前表征列块作为对照；这仍不保证其余行为不受影响。
3. **盲改DPet跨模态Q/K。** 同作者开发版将整句文本作为唯一一个key/value token；该路径softmax只有一个元素，因此在正常有限数值下其权重恒1，Q/K变化不会改变注意力输出。这是对开发版指定路径的静态数学结论，不是已确认的论文最终实现缺陷。若研究这一路径，V和output projection才是有直接输出影响的候选。[代码L1815–1840](https://github.com/tju-dhj/DPed-VLN/blob/54ceed00efeabcd7ea4e8ba69e57d072679572c0/habitat-baselines/habitat_baselines/rl/ddppo/policy/resnet_policy.py#L1815-L1840)。

当前Falcon评测的STOP会终止episode，不能通过提高STOP概率实现等待让行；pause/backward虽有实现但没有启用。[动作实现](https://github.com/Zeying-Gong/Falcon/blob/d15ef512c4b1451f9daeaf6d4d7ecc702ed57430/falcon/additional_action.py#L38-L75)。

## 4. 怎样定义Approach SOTA

先固定任务。Falcon/NavThinker是社会点目标导航；DPed-VLN是语言导航，两组数字不能直接比较。

- 社会点目标导航：NavThinker论文表I同口径Social-HM3D复评，Falcon SR56.26、NavThinker59.46，相差3.20个百分点。这可以作为一个明确的论文内追赶目标，不能据此称2026-11-03全领域最新SOTA，也不能把差距解释成容易弥补。Social-MP3D中Falcon SR51.67反而高于NavThinker47.33，因此还应保留跨域优势。[论文表I](https://arxiv.org/html/2603.15359v2)。
- DPed-VLN：论文表3中DPet-RL level1 SR37.13/SPL33.36/HCR42.45；level2 SR38.55/SPL36.35/HCR36.70。它在文中比较方法里成功和效率最好，但安全指标不是全部最佳。两级指令分别比较，不能混为同一SOTA。[论文表3](https://arxiv.org/html/2609.21504v1)。

首轮更可检验的目标是：保持SR/SPL时降低HCR，或在同等碰撞约束下提高SR。另记录逐回合“成功且无碰撞”的比例，不能用汇总SR乘以(1−HCR)代替这个联合事件。

## 5. 最小实验与否定条件

1. 取得匹配代码/config/checkpoint，复现基础评测；核对传感器、动作索引、STOP、随机性、episode终止逻辑。张量编辑本身小，完整Habitat渲染和闭环回合仍有计算与场景数据成本。
2. 在训练场景留出的开发集收集一种高频故障，并有外观相似的正常保留集。区分合理重复前进与真正无进展震荡；统计该类故障可解释的失败占比。
3. 验证隐藏表征是否已包含可用线索；临时激活干预可用于诊断，但最终必须保存并重载编辑checkpoint，证明无hook时仍有效。
4. 固定反馈预算，对比原模型、bias-only校准、同范数随机秩一编辑、目标编辑、相同数据预算的动作头调优。记录全部失败候选、模型推理量、仿真步数与编辑器成本，不能只记调用次数。
5. 冻结补丁后在未参与选方向/强度的场景和行人seed上闭环评估，报告配对SR/SPL/HCR/PSC、超时、回合时长与按场景的不确定性。

若收益只出现在开发场景、正常行为明显退化、仅靠早停降低碰撞、或不优于bias-only与随机对照，应先排除实现问题，再停止扩大该候选。开放环动作正确率提升不能替代闭环导航结果。

## 6. 创新空间必须进一步收窄

[VLN Interpreting and Steering](https://arxiv.org/html/2609.24576v1)已经用激活向量引导导航恢复，实机由操作员识别失败后触发；没有永久修改权重。[MoRE/Behavior Uncloning](https://arxiv.org/html/2606.29201v1)通过训练分类器与反向传播把行为偏好写入策略，含四足导航。[SARP](https://arxiv.org/html/2411.04408v1)也已用预测模型与约束优化修复导航安全。

值得检验但尚未证明新颖的问题是：**固定小反馈预算下，LLM能否诊断导航局部故障、用无反向传播的少量权重修改实现跨场景修复，并优于便宜的校准、随机修改和轻量调优？** 只把“编辑权重”用于导航，或得到一个比原始模型高的分数，尚不足以回答这个问题。
